# Poche rule coverage

This ledger decomposes the normative statements in `docs/main.typ` into stable
rule IDs. IDs survive prose movement and source-line changes; when the rulebook
changes, update the source anchor and disposition without recycling an ID.

“Comprehensive” means every applicable rule has evidence in every model track.
It does not mean every full-deck execution is exhaustively enumerated. Every
bounded or exhaustive result must name its finite scope separately.

## Dispositions

- `todo`: required by the current goal but not yet supported by evidence.
- `modeled: ...`: encoded, with an evidence anchor following the colon.
- `checked: ...`: asserted/model-checked, with an evidence anchor.
- `queried: ...`: covered by a native relational query and corpus.
- `validated: ...`: executable evidence has passed.
- `n/a: ...`: the track cannot meaningfully represent this physical,
  documentary, or authority-only rule; the reason is mandatory.
- `deferred: ...`: outside the current goal; the reason is mandatory.

Plain `cargo run -p poche-xtask -- coverage audit` checks structure and reports
remaining `todo` cells. `--track rust|alloy|nusmv|prolog` and `--all` are strict:
they fail while a selected applicable cell remains `todo`.

The future-RL column is an architectural relevance flag, not a fifth model
track or a current-goal completion obligation.
